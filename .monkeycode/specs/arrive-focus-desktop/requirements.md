# 抵达 Focus Windows 桌面版需求规格

Feature Name: `arrive-focus-desktop`
Updated: 2026-07-18
Status: Confirmed scope, design in progress

## Introduction

抵达 Focus 是一款面向 Windows 10/11 的纯本地专注系统。产品以长期项目、每日任务、重复计划、专注计时和周期复盘为核心，并通过桌面小组件、系统托盘、原生通知、后台计时、全局快捷键和任务栏状态提供桌面级体验。应用免登录运行，用户数据保存在本机，并支持可移植备份。

参考产品：`https://8bfz9eam.showcase.monkeycode-ai.online/`

## Glossary

- **应用**：抵达 Focus Windows 桌面应用。
- **项目**：由项目资料、任务集合和进度统计组成的长期工作单元。
- **任务**：包含标题、分类、所属项目、计划日期、计划时间和完成状态的行动项。
- **检查项**：隶属于任务的轻量完成项。
- **重复规则**：描述任务重复频率、执行时间和有效日期范围的计划模板。
- **任务实例**：重复规则在一个执行日期生成的独立待办记录。
- **今日汇总**：聚合今日普通任务、项目任务、重复任务实例和逾期任务的统一视图。
- **桌面小组件**：与主窗口共享数据并可在桌面贴附或置顶浮窗模式运行的紧凑窗口。
- **专注轮次**：围绕一个任务执行的计时过程。
- **有效专注**：自然结束或由用户确认提前完成的专注轮次。
- **中断**：专注轮次运行期间发生的暂停行为。
- **本地数据库**：位于 Windows 应用数据目录中的 SQLite 数据库。
- **后台运行**：主窗口关闭后，应用通过系统托盘保持计时和数据服务可用的状态。
- **日界线**：本地时间每日 00:00，用于划分日统计数据。

## Requirements

### Requirement 1：首次启动与桌面外壳

**User Story:** 作为 Windows 用户，我希望通过安装包完成安装并快速进入应用，以便把抵达 Focus 作为日常桌面工具使用。

#### Acceptance Criteria

1. WHEN 用户运行 NSIS 安装包，安装程序应提供安装目录选择、桌面快捷方式选择和开始菜单入口。
2. WHEN 用户首次启动应用，应用应在 3 秒内显示可交互主界面，计时从进程启动开始测量，测试设备基线为 4 核 CPU、8 GB 内存和 SSD。
3. WHEN 用户再次启动已在后台运行的应用，应用应激活现有主窗口。
4. WHILE 主窗口处于普通状态，应用应记忆窗口尺寸、位置和最大化状态，并在下一次启动时恢复到可见显示区域。
5. IF 保存的窗口位置位于当前显示器边界外，应用应在主显示器中央显示窗口。

### Requirement 2：每日任务管理

**User Story:** 作为专注工作者，我希望规划和管理每日任务，以便明确当前行动目标。

#### Acceptance Criteria

1. WHEN 用户创建任务，应用应保存标题、分类、可选所属项目、计划日期、可选计划时间和可选检查项。
2. WHEN 用户编辑、完成、恢复或移除任务，应用应在 300 毫秒内更新界面和本地数据库。
3. WHILE 用户查看今日页面，应用应按工作、学习、健康和生活分类展示任务，并提供全部、待完成和已完成筛选。
4. WHEN 用户输入搜索词，应用应按任务标题实时筛选当前任务集合。
5. IF 用户选择早于当前本地日期的计划日期，应用应阻止提交并说明有效日期范围。
6. WHEN 用户完成任务，应用应记录完成时间，并将结果纳入日历和统计。

### Requirement 3：专注计时

**User Story:** 作为专注工作者，我希望围绕选定任务进行稳定计时，以便完成可复盘的深度工作轮次。

#### Acceptance Criteria

1. WHEN 用户选择专注时长，应用应提供 15、25、50 分钟预设和 1 至 180 分钟自定义时长。
2. WHEN 用户开始专注，应用应保存轮次开始时间、目标结束时间、任务标识和计划时长。
3. WHEN 用户暂停或继续专注，应用应更新轮次状态、剩余时长和中断次数。
4. WHEN 用户确认提前完成，应用应将实际专注秒数保存为有效专注记录。
5. WHEN 倒计时到达目标结束时间，应用应保存有效专注记录并触发完成提醒。
6. IF 应用经历系统休眠、锁屏、进程调度延迟或系统时间跳变，应用应根据持久化目标时间在 2 秒内校准剩余时长。
7. WHILE 专注轮次运行，任务栏进度应显示剩余比例，托盘菜单应显示剩余时间和暂停操作。
8. WHEN 输入控件未获得焦点，空格键应控制开始、暂停或继续当前轮次。

### Requirement 4：后台运行与系统托盘

**User Story:** 作为 Windows 用户，我希望关闭主窗口后计时持续运行，以便在其他应用中工作。

#### Acceptance Criteria

1. WHEN 用户关闭主窗口且后台运行已启用，应用应隐藏主窗口并保持托盘图标可用。
2. WHEN 用户单击托盘图标，应用应恢复并聚焦主窗口。
3. WHEN 用户打开托盘菜单，应用应提供显示窗口、开始或暂停当前轮次、创建快速任务和退出应用操作。
4. WHEN 用户选择退出应用，应用应持久化当前轮次状态并在 2 秒内结束进程。
5. WHILE 专注轮次运行，后台计时结果应与主窗口持续可见时的结果保持一致，允许误差小于 2 秒。

### Requirement 5：Windows 通知与快捷操作

**User Story:** 作为专注工作者，我希望在关键节点获得系统提醒并快速控制计时，以便减少窗口切换。

#### Acceptance Criteria

1. WHEN 专注轮次完成，应用应发送包含任务名称和实际时长的 Windows 原生通知，并播放可配置提示音。
2. WHEN 应用缺少通知权限，应用应在设置页显示权限状态和系统设置入口。
3. WHEN 用户启用全局快捷键，应用应支持显示主窗口、开始或暂停专注、创建快速任务三项可配置操作。
4. IF 用户选择的全局快捷键已被系统或其他应用占用，应用应保留原配置并显示冲突原因。
5. WHEN 用户更改开机启动设置，应用应立即同步 Windows 登录启动项状态。

### Requirement 6：日历与复盘统计

**User Story:** 作为专注工作者，我希望查看任务和专注趋势，以便调整工作节奏。

#### Acceptance Criteria

1. WHEN 用户打开日历，应用应提供周、月和年视图，并突出当前日期和选中日期。
2. WHEN 用户选择日期，应用应展示该日期的计划任务、完成任务和专注轮次。
3. WHEN 用户切换分类筛选，应用应同步更新日期内容和统计指标。
4. WHILE 用户查看统计页，应用应展示计划完成率、完成任务数、专注分钟数、有效专注轮次和活跃天数。
5. WHEN 用户跨越日界线，应用应按专注轮次完成时间归属日统计。
6. IF 统计范围内缺少记录，应用应显示数值为零的空状态和开始记录的入口。

### Requirement 7：便签与周目标

**User Story:** 作为专注工作者，我希望快速记录干扰想法和本周目标，以便保持当前任务连续性。

#### Acceptance Criteria

1. WHEN 用户编辑随手便签，应用应在停止输入 500 毫秒内自动保存内容。
2. WHEN 用户按下 Ctrl+Enter，应用应立即保存便签并显示保存反馈。
3. WHEN 用户创建周目标，应用应保存目标名称、分类和目标数量。
4. WHEN 关联任务或专注数据变化，应用应在 300 毫秒内重新计算周目标进度。

### Requirement 8：本地数据、备份与恢复

**User Story:** 作为重视隐私的用户，我希望数据保存在本机并能够备份，以便离线使用和自主迁移。

#### Acceptance Criteria

1. WHILE 应用运行，任务、专注轮次、便签、目标和偏好应保存到本地数据库。
2. WHEN 用户导出备份，应用应通过原生文件保存对话框生成包含格式版本、导出时间和完整业务数据的 JSON 文件。
3. WHEN 用户选择备份文件，应用应在写入数据库前校验格式版本、字段类型、记录数量和引用关系。
4. WHEN 备份通过校验，应用应显示任务数、专注轮次数、日期范围和替换影响，并请求用户确认。
5. WHEN 用户确认恢复，应用应在单个数据库事务中替换业务数据并保留恢复前自动快照。
6. IF 恢复过程失败，应用应回滚事务并显示可执行的错误说明。
7. WHEN 数据库结构升级，应用应按版本顺序执行迁移并记录迁移结果。

### Requirement 9：外观、语言与无障碍

**User Story:** 作为长期使用桌面工具的用户，我希望界面适应系统与个人偏好，以便保持舒适和一致的使用体验。

#### Acceptance Criteria

1. WHEN 用户选择自动外观，应用应跟随 Windows 明亮或深色模式变化。
2. WHEN 用户选择主题，应用应提供薄荷序章、黑金沉浸、办公蓝和粉红柔光四套配色并立即应用。
3. WHEN 用户选择语言，应用应支持简体中文、英文和跟随系统语言。
4. WHILE Windows 减少动态效果设置已启用，应用应停用装饰性循环动画，并保留状态变化反馈。
5. WHILE 用户通过键盘操作，所有主要功能应具有可见焦点、可读名称和连续导航顺序。
6. WHILE Windows 文本缩放设置为 125%，主要页面应保持任务创建、计时控制和设置操作完整可用。

### Requirement 10：设置与生命周期

**User Story:** 作为 Windows 用户，我希望控制应用的桌面行为，以便匹配个人工作习惯。

#### Acceptance Criteria

1. WHEN 用户打开设置页，应用应展示语言、外观、主题、提示音、后台运行、开机启动、全局快捷键和数据管理设置。
2. WHEN 用户修改设置，应用应在 300 毫秒内保存并应用可即时生效的设置。
3. WHEN 应用检测到新版本，应用应显示版本号、更新说明和下载确认入口。
4. WHEN 更新包下载完成，应用应在用户确认后安全退出并启动安装流程。
5. IF 更新检查失败，应用应保留当前版本运行并记录可诊断错误。

### Requirement 11：桌面小组件

**User Story:** 作为 Windows 用户，我希望把今日任务和专注状态贴在桌面上，以便打开电脑后立即看到当天行动。

#### Acceptance Criteria

1. WHEN 用户启用桌面小组件，应用应创建独立无边框透明窗口，并显示时钟、日期、当前专注和今日任务摘要。
2. WHEN 用户选择桌面贴附模式，桌面小组件应保持在桌面图标层附近，并由普通应用窗口覆盖。
3. WHEN 用户选择置顶浮窗模式，桌面小组件应保持在普通应用窗口上方。
4. WHEN 用户锁定桌面小组件，应用应启用鼠标穿透并保留解锁快捷入口。
5. WHEN 用户解锁桌面小组件，应用应支持拖动、缩放、透明度调整和显示模块选择。
6. WHEN 用户选择组件尺寸，应用应提供紧凑、标准和展开三种布局，并分别容纳 1、5 和 10 条今日任务。
7. WHILE 专注轮次运行，桌面小组件应在 2 秒内同步剩余时间、任务名称和暂停状态。
8. WHEN Windows Explorer、显示器连接或缩放比例发生变化，应用应在 5 秒内将桌面小组件恢复到可见工作区。
9. IF 桌面贴附操作失败，应用应切换到普通浮窗模式并显示一次状态说明。
10. WHILE Windows 文本缩放设置为 125%，桌面小组件的时钟、任务和主要操作应保持完整可用。

### Requirement 12：长期项目管理

**User Story:** 作为承担长期工作的用户，我希望把相关任务集中到项目中，以便持续跟踪范围、进度和投入时间。

#### Acceptance Criteria

1. WHEN 用户创建项目，应用应保存项目名称、说明、颜色、图标、开始日期、可选目标日期和状态。
2. WHEN 用户在项目中创建任务，应用应将任务、检查项和专注轮次关联到所属项目。
3. WHILE 用户查看项目列表，应用应展示进行中、已暂停、已完成和已归档项目，并支持按状态筛选。
4. WHEN 项目任务状态变化，应用应在 300 毫秒内重新计算任务完成比例、完成数量和累计专注时长。
5. WHEN 用户打开项目详情，应用应展示项目概览、任务分组、近期活动、截止风险和专注投入。
6. WHEN 用户完成全部必要任务，应用应提示用户确认项目完成状态。
7. WHEN 用户归档项目，应用应从活动项目列表移出项目，并保留项目任务、实例和专注历史。
8. IF 用户移除包含任务或专注历史的项目，应用应提供归档项目或解除任务关联两种处理方式。

### Requirement 13：定时任务与今日汇总

**User Story:** 作为建立固定工作习惯的用户，我希望任务按计划自动出现在当天列表中，以便每天打开电脑后明确当天行动。

#### Acceptance Criteria

1. WHEN 用户为任务设置重复规则，应用应支持每天、工作日、每周指定星期、每月指定日期和自定义间隔。
2. WHEN 用户设置重复规则，应用应保存本地执行时间、开始日期、可选结束日期和可选所属项目。
3. WHEN 本地日期进入重复规则的有效执行日，应用应生成唯一任务实例并加入今日汇总。
4. WHEN 用户完成任务实例，应用应保存本次完成记录并维持后续重复规则有效状态。
5. WHEN 用户处理任务实例，应用应提供完成、跳过本次、延后到今日其他时间和顺延到明日操作。
6. WHEN 用户修改重复任务，应用应提供仅修改本次和修改当前日期之后计划两种范围。
7. WHILE 用户查看今日汇总，应用应聚合今日普通任务、今日项目任务、今日重复任务实例和逾期任务，并按计划时间、优先级和创建顺序排序。
8. WHEN 任务实例到达计划时间，应用应发送 Windows 原生通知，并在桌面小组件中突出该任务。
9. WHEN 应用在多个日期后重新启动，应用应补生成有效规则在缺失日期内的实例，并将未处理实例标记为逾期。
10. IF 每月规则指定日期超出目标月份天数，应用应在目标月份最后一个自然日生成任务实例。
11. WHILE 桌面小组件处于标准或展开布局，桌面小组件应显示任务时间、标题、所属项目、重复标识和逾期状态。
12. WHEN 用户暂停或结束重复规则，应用应保留已生成实例和历史完成记录。

### Requirement 14：统一视觉与交互体系

**User Story:** 作为长期使用桌面工具的用户，我希望主应用和桌面小组件保持一致且清晰的视觉语言，以便快速识别项目、任务和专注状态。

#### Acceptance Criteria

1. WHILE 应用展示主界面或桌面小组件，应用应使用共享颜色、字体、间距、圆角、阴影和动效设计令牌。
2. WHEN 信息具有项目、分类、优先级、重复或逾期属性，应用应使用文字标签与颜色共同表达状态。
3. WHILE 用户查看今日汇总，应用应在一个视图中区分当前专注、下一项任务、定时任务、项目任务和逾期任务。
4. WHILE 用户查看专注空间，应用应将剩余时间作为最高视觉层级，并将次要统计保持在辅助区域。
5. WHEN 用户切换主题或明暗模式，主窗口和桌面小组件应在 300 毫秒内同步更新。
6. WHILE 应用显示正文或交互文字，文字与背景对比度应达到 WCAG 2.2 AA 要求。

## Out of Scope for Version 1.0

- 账户体系、多设备云同步和团队协作。
- 网站屏蔽、应用进程限制和强制锁定模式。
- 移动端、macOS 和 Linux 安装包。
- 在线日历、邮件和第三方任务平台集成。
- AI 任务拆解和自动规划。
- 项目成员、权限分配和多人协作。

## Release Acceptance

- Windows 10 22H2 x64 和 Windows 11 23H2 x64 完成安装、升级、卸载和重启验证。
- 核心流程“创建项目 → 创建重复任务 → 生成今日实例 → 小组件提醒 → 开始专注 → 后台运行 → 完成记录 → 日历复盘 → 导出备份”通过端到端测试。
- 连续运行 8 小时后，空闲内存保持稳定，后台计时累计误差小于 2 秒。
- 数据恢复故障注入测试证明事务回滚和恢复前快照可用。
- 安装包和可执行文件使用 Windows 代码签名证书签名后进入公开发布流程。
