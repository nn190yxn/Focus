# 抵达 Focus 备忘录中心需求文档

Feature Name: `arrive-focus-memo-center`
Updated: 2026-07-23
Status: Draft for review

## Introduction

抵达 Focus 将新增独立备忘录中心，用于长期保存与今日随手便签不同的多条备忘内容。首版提供创建、编辑、删除、搜索、标签、置顶、一次性提醒和重复提醒能力，并延续应用现有的本地优先、免登录、SQLite 权威数据、Windows 原生通知、备份恢复、双语和无障碍约束。

## Glossary

- **备忘录中心**：主窗口左侧导航中的独立页面，用于管理全部备忘录。
- **备忘录**：包含标题、纯文本正文、标签、置顶状态、可选提醒时间和审计时间的本地记录。
- **标签**：用户为备忘录输入的自由文本分类名称。
- **一次性提醒**：在一个明确的本地日期和时间触发一次的 Windows 原生通知。
- **重复提醒**：按每天、工作日、每周指定星期、每月指定日期或自定义间隔持续计算通知时间的提醒规则。
- **随手便签**：今日页现有的单日快速记录，与备忘录保持独立。
- **本地数据库**：位于 Windows 应用数据目录中的 SQLite 数据库。

## Requirements

### Requirement 1：独立入口与备忘录列表

**User Story:** 作为专注工作者，我希望通过独立页面查看全部备忘录，以便集中管理长期记录。

#### Acceptance Criteria

1. WHEN 用户打开主窗口，应用应在左侧主导航中显示“备忘录”入口。
2. WHEN 用户打开备忘录中心，应用应显示备忘录标题、正文摘要、标签、提醒状态、置顶状态和最后更新时间。
3. WHILE 备忘录中心存在置顶记录，应用应先按置顶时间倒序显示置顶记录，再按更新时间倒序显示其余记录。
4. IF 备忘录中心缺少记录，应用应显示空状态、新建入口和用途说明。
5. WHEN 用户从其他主页面返回备忘录中心，应用应恢复最近使用的搜索词和标签筛选状态，直至主窗口关闭。

### Requirement 2：创建、编辑与持久化

**User Story:** 作为专注工作者，我希望快速创建和修改备忘录，以便持续补充重要信息。

#### Acceptance Criteria

1. WHEN 用户选择新建备忘录，应用应创建包含空标题、空正文、空标签和空提醒的编辑草稿。
2. WHEN 用户修改标题、正文、标签或置顶状态，应用应在停止输入或操作 500 毫秒内保存当前备忘录。
3. WHEN 用户按下 Ctrl+Enter，应用应立即保存当前备忘录并显示保存结果。
4. WHILE 备忘录保存进行中，应用应保留用户在保存请求发出后继续输入的内容。
5. IF 保存失败，应用应保留当前草稿、显示可执行的错误提示并提供重新保存入口。
6. WHEN 标题为空且正文包含非空内容，应用应在列表中使用正文首个非空行的前 40 个字符作为显示摘要。
7. WHILE 用户编辑备忘录，应用应接受最多 200 个字符的标题和最多 20000 个字符的纯文本正文。

### Requirement 3：搜索与筛选

**User Story:** 作为拥有多条记录的用户，我希望搜索和筛选备忘录，以便快速找到目标内容。

#### Acceptance Criteria

1. WHEN 用户输入搜索词，应用应在停止输入 200 毫秒内按标题、正文和标签执行不区分大小写的包含匹配。
2. WHEN 用户选择一个标签，应用应只显示包含该标签的备忘录。
3. WHEN 用户同时输入搜索词并选择标签，应用应显示同时满足搜索与标签条件的备忘录。
4. IF 搜索与筛选缺少匹配记录，应用应显示清除条件入口和零结果说明。
5. WHEN 用户清除搜索与筛选条件，应用应恢复完整备忘录列表及既定排序。

### Requirement 4：标签管理

**User Story:** 作为需要组织信息的用户，我希望用标签分类备忘录，以便按主题浏览记录。

#### Acceptance Criteria

1. WHEN 用户为备忘录输入标签名称，应用应去除标签名称首尾空白并保存非空名称。
2. WHEN 用户输入与现有标签仅大小写不同的名称，应用应复用现有标签。
3. WHILE 用户编辑单条备忘录，应用应允许关联最多 10 个标签，每个标签名称最多包含 30 个字符。
4. WHEN 用户移除备忘录中的标签，应用应保留其他备忘录与该标签的关联。
5. WHEN 标签缺少任何备忘录关联，应用应从标签筛选列表中移除该标签。

### Requirement 5：置顶

**User Story:** 作为专注工作者，我希望置顶重要备忘录，以便优先看到高频信息。

#### Acceptance Criteria

1. WHEN 用户置顶备忘录，应用应记录置顶时间并将该记录移动到置顶分组首位。
2. WHEN 用户取消置顶备忘录，应用应按最后更新时间将该记录放回普通分组。
3. WHILE 搜索或标签筛选生效，应用应在匹配结果内继续应用置顶优先排序。
4. WHEN 置顶状态保存失败，应用应恢复服务端权威状态并显示操作失败提示。

### Requirement 6：一次性提醒与重复提醒

**User Story:** 作为需要在特定时间回顾信息的用户，我希望为备忘录设置提醒，以便及时处理记录内容。

#### Acceptance Criteria

1. WHEN 用户设置一次性提醒，应用应要求选择一个晚于当前时间的本地日期和时间。
2. WHEN 用户设置重复提醒，应用应支持每天、工作日、每周指定星期、每月指定日期和自定义间隔。
3. WHEN 用户设置重复提醒，应用应保存本地执行时间、开始日期、可选结束日期和 IANA 时区。
4. WHEN 备忘录提醒到达计划时间，应用应发送包含备忘录显示标题的 Windows 原生通知。
5. WHEN 用户点击备忘录提醒通知，应用应显示主窗口并打开对应备忘录。
6. WHEN 用户修改提醒规则，应用应使用新规则计算尚未发送的提醒时间。
7. WHEN 用户取消提醒，应用应停止该提醒的后续投递。
8. WHEN 一次性提醒成功发送，应用应把提醒状态更新为已提醒，并保持备忘录内容可继续编辑。
9. WHEN 重复提醒成功发送，应用应保留提醒规则并计算下一次有效提醒时间。
10. IF 每月提醒指定日期超出目标月份天数，应用应在目标月份最后一个自然日安排提醒。
11. IF 系统通知权限缺失，应用应保存提醒并显示通知权限说明和系统设置入口。
12. IF 通知发布失败，应用应记录可重试状态，并在后续通知协调周期中再次尝试投递。
13. WHILE 同一提醒发生时间已经成功发送，应用应拒绝重复发送该提醒通知。

### Requirement 7：删除保护

**User Story:** 作为管理备忘录的用户，我希望安全删除已无用途的记录，以便保持列表整洁。

#### Acceptance Criteria

1. WHEN 用户选择删除备忘录，应用应显示包含备忘录显示标题的确认对话框。
2. WHEN 用户确认删除，应用应在单个数据库事务中删除备忘录、标签关联和未发送提醒。
3. WHEN 用户取消删除，应用应保留备忘录及其全部关联数据。
4. IF 删除失败，应用应保留备忘录、恢复列表权威状态并显示错误提示。

### Requirement 8：本地数据、备份与恢复

**User Story:** 作为重视隐私的用户，我希望备忘录保存在本机并进入备份，以便离线使用和自主迁移。

#### Acceptance Criteria

1. WHILE 应用运行，应用应把备忘录、标签、标签关联和提醒状态保存到本地数据库。
2. WHEN 用户导出备份，应用应把备忘录、标签、标签关联和提醒记录写入版本化 JSON 数据集。
3. WHEN 用户检查备份，应用应在恢复前校验备忘录字段、标签引用、提醒时间和记录唯一性。
4. WHEN 用户恢复有效备份，应用应在同一个恢复事务中替换备忘录相关数据并保留恢复前快照。
5. IF 恢复过程失败，应用应回滚备忘录相关写入并保留恢复前数据。

### Requirement 9：一致性、国际化与无障碍

**User Story:** 作为长期使用桌面工具的用户，我希望备忘录符合现有界面和操作习惯，以便顺畅使用新功能。

#### Acceptance Criteria

1. WHILE 用户使用备忘录中心，应用应使用现有主题、明暗模式、间距、状态色和共享组件。
2. WHEN 用户切换简体中文、英文或跟随系统语言，应用应同步更新备忘录页面及通知文案。
3. WHILE 用户通过键盘操作，应用应为新建、搜索、筛选、置顶、提醒、保存和删除提供可见焦点与可读名称。
4. WHILE Windows 文本缩放设置为 125%，应用应保持备忘录列表、编辑器和主要操作完整可用。
5. WHEN 备忘录数据在一个窗口或通知入口中变化，应用应通过领域事件重新读取 SQLite 权威状态。

## Scope Boundaries

首版包含纯文本备忘录、自由文本标签、单标签筛选、置顶、一次性提醒，以及每天、工作日、每周、每月和自定义间隔重复提醒。富文本、图片附件、文件附件、多人同步、云端同步、归档和回收站进入后续版本评估。

今日页“随手便签”继续按日期独立保存。备忘录中心与随手便签之间不提供自动复制或转换。

## Validation Notes

- 每条验收标准使用明确触发条件和单一可测试结果。
- “备忘录”“标签”“一次性提醒”和“随手便签”在全文中使用统一术语。
- 性能相关标准使用 200 毫秒或 500 毫秒阈值。
- 删除、恢复、通知失败和保存竞态均定义了可验证行为。
